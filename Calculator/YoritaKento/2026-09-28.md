# 9月28日 勉強会のおさらい

C#・Windows Forms｜電卓の数字入力と表示の切り替え

## 1. 今回のゴール

**演算子を押した後、次の数字を入力すると表示が上書きされる仕組みを理解すること**です。今回は計算結果を求める処理ではなく、数字の表示を切り替える処理に取り組みました。

## 2. 実現したい動き

表示が「0」のときに「1」を押したら、「01」ではなく「1」に上書きします。さらに「2」を押したら「12」とつなげます。この、文字を後ろにつなげる処理を**文字列結合**と呼びます。

演算子を使う場合は、次の動きを目指します。

```text
押す順番： 「3」 → 「＋」 → 「1」
画面表示：   3  →    3   →   1
```

**「＋」を押した瞬間ではなく、その後に数字を押したときに上書きする**ことがポイントです。

## 3. なぜ変数が必要なのか

数字ボタンの処理では、その前に演算子が押されたかどうかを判断する必要があります。そのため、演算子が押されたことを変数に記憶します。

今回は「押された／押されていない」という2択なので、`true`と`false`を扱う **`bool`型**を使いました。最初は`false`にしておき、プラスボタンを押したら`true`を代入します。数字ボタン側では、この値を`if`文で確認し、上書きするかどうかを判断します。

また、あるボタンのイベント内で宣言した変数は、別のボタンのイベントから参照できません。今回は、各イベントの外に変数を宣言して共通で使いました。授業では、この変数を**「グローバル変数」**と呼んで説明しました。

覚えておきたい流れは、**「演算子側で記憶する → 数字側で確認する → 処理を分ける」**です。

## 4. 書くときの注意点

**宣言と代入を区別しましょう。** 変数名を`plus`とした書き方の例では、`bool plus = false;`は変数を新しく作る「宣言と初期化」、`plus = true;`は既存の変数の値を変更する「代入」です。値を変更するだけなら、先頭に`bool`は付けません。

また、`=`は代入、`==`は比較です。エラーが出たら、サンプルと自分のコードを、括弧やピリオドなどの記号まで見比べましょう。

**後から読めるようにコメントも付けましょう。** 個々の処理には`//`の後にスペースを空けて説明を書き、関数・イベント全体の説明には、授業で確認した`///`を使います。変数名を分かりやすくし、不要な行も整理してください。

## 5. 理解を確かめよう

資料をいったん閉じて、自分の言葉で答えてみましょう。

1. 演算子を押したことを、なぜ変数に記憶する必要がありますか？
2. プラスボタンと数字ボタンで同じ変数を使うには、どこに宣言しますか？
3. `bool plus = false;`と`plus = true;`は、何が違いますか？

答えに迷ったところは、上の説明と自分のコードを見直してください。
