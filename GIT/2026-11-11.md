## 1 今日のゴール

SQLで対象のデータを正しく更新・削除・取得できるようにすることと、Gitを使って自分の変更を共有し、相手の変更を取り込む流れを理解することです。

## 2 実現したい動き／学んだこと

### SQL課題の見直し

- **UPDATE**：日付などの条件に合うデータを、1つの更新文でまとめて更新する。
- **DELETE**：`AND`・`OR`と括弧を使い、削除したいデータだけを対象にする。
- **INNER JOIN（内部結合）**：必要なテーブルを結び付け、指定された項目を取得する。

基本的な更新・削除には正しく書けているものもありました。日付条件付きの更新、複数条件の削除、結合課題には修正や続きの調査が必要です。

### Gitの操作

授業では、Git・SourceTreeの導入とGitHubとの連携を進め、練習用リポジトリのクローン、自分用の「ケント」ブランチの作成を行いました。ファイルの追加・コミット・プッシュと、講師の変更をプルして履歴やファイルの内容を確認するところまで実施しました。

## 3 考え方

### 対象をSQLの条件で決める

「2026年6月4日より前のユーザーの`is_active`を0にする」課題では、`SELECT`の結果を目で見て、ユーザーIDを1件ずつ指定していました。しかし、データが増えると手作業では対応できません。**日付条件を`WHERE`に書き、1つの`UPDATE`文で対象をまとめて更新する**と考えます。

削除条件が「オーダーIDが101、かつプロダクトIDが1または2」なら、「プロダクトIDが1または2」の部分を括弧でまとめます。`OR`の範囲が違うと、意図しないデータも対象になります。

内部結合では、「どのテーブルが必要か」「何を条件に結ぶか」「取得する項目がそろっているか」を確認します。

### 変更をローカルに記録し、リモートと共有する

**Git**は変更履歴を管理する仕組み、**GitHub**はネット上でリポジトリを共有するサービス、**SourceTree**はGitを画面から操作するツールです。リポジトリは、ファイルや変更履歴を管理する場所です。自分のPC側を「ローカル」、ネット上の共有先を「リモート」と呼びます。

| 操作・用語 | 意味 |
| --- | --- |
| クローン | リモートのリポジトリを、履歴ごと自分のPCに複製する |
| ブランチ | 作業の流れを分けて変更を進める仕組み |
| ステージング | 次のコミットに含める変更を選ぶ |
| コミット | 選んだ変更を、説明コメントとともにローカルの履歴に記録する |
| プッシュ | ローカルのコミットやブランチをリモートに反映する |
| プル | リモートの変更を取得し、ローカルに取り込む |

基本の流れは、**ファイルを編集・保存 → ステージング → コメントを付けてコミット → プッシュ**です。相手の変更を自分のPCに反映するときはプルします。ブランチの変更を合流させる「マージ」は、今回は考え方の説明までで、詳しい操作は後で学びます。

## 4 注意点

- SQLは書くだけで終わらず、実行して対象データと取得項目が正しいか確認する。不要なテーブルを結合しない。
- 条件の括弧、取得項目の抜け、結合先の間違いを見直す。`=`の前後は半角スペースを入れて読みやすくする。
- コミットだけではGitHubに共有されない。共有するにはプッシュが必要。
- 今回のプッシュエラーは、共有先への権限がなかったことが原因。招待を承認した後、プッシュに成功した。
- 分からない問題を飛ばさず、「内部結合 複数」などで調べて試す。困ったときは講師に相談する。
