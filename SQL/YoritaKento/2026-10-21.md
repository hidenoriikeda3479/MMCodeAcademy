SQL｜データベースの基礎と、データの取得・登録

## 1. 今回のゴール

**データベースとSQLの役割を説明し、必要なデータを取得・登録できるようになること**です。今回は、取得する`SELECT`文と、登録する`INSERT`文を中心に練習しました。

## 2. 実現したい動き

SQL Server Management Studioで練習用データベースを選び、SQLを書いて実行しました。ユーザーや商品の情報を表示し、条件に合うデータだけに絞り込みます。さらに、新しいユーザーを登録し、`SELECT`文で追加されたことを確認しました。

**「SQLを書く → 実行する → 結果が目的どおりか確認する」**までが一連の作業です。

## 3. 処理の考え方

### データベース・テーブル・SQL

データベースは、データを整理して保存する場所です。その中の表を**テーブル**、名前や金額などの項目を**カラム（列）**、1件分のデータを**レコード（行）**と呼びます。各列には、入れられるデータの種類を決める「型」があります。

SQLは、データベースに命令するための言葉です。授業では、登録・取得・更新・削除の基本操作をまとめて**CRUD**と呼ぶことを確認しました。

### SELECT：必要なデータを取得する

`SELECT`の後に取得したい列、`FROM`の後にテーブル、`WHERE`の後に絞り込み条件を書きます。複数の列はカンマで区切り、全列を取得する場合は`*`を使います。

授業で取り組んだ「商品テーブルから、IsActiveが1で、金額が2,000円以上のデータを取得する」という条件を整理すると、次の形です。

```sql
SELECT *
FROM Products
WHERE IsActive = 1
  AND Price >= 2000;
```

**`AND`は両方の条件を満たす場合、`OR`はどちらかの条件を満たす場合**です。また、`>`は指定した値を含まず、`>=`はその値も含みます。

### INSERT：新しいデータを登録する

`INSERT INTO`の後にテーブル名と列名を指定し、`VALUES`の後に登録する値を並べます。**指定した列と値は、同じ順番で対応させる**ことが重要です。

列には、型だけでなく「制約」もあります。今回の例では、ユーザーを識別する`UserID`にプライマリーキー、`Email`にユニークキーがあり、重複する値を登録するとエラーになることを確認しました。

また、受講生側の`UserID`には自動採番が設定されていたため、授業の後半では、`UserID`を指定せずに登録する形に変更しました。

## 4. 書くときの注意点

**まず、操作するデータベース・テーブル・列が合っているか確認しましょう。** 商品を扱う`Products`と、ユーザーを扱う`Users`を混同しないことが大切です。名前の末尾の`s`やスペルも、実際の定義と見比べてください。

SQLでは、文字列をシングルクォーテーション`'...'`で囲みます。授業で扱った日付も同様に囲み、数値は囲まずに記載しました。命令語の大文字表記、スペース、改行をそろえ、コメントには`--`を使います。

授業中には文字列検索や文字化けの問題もあり、データベース設定の見直しを行いました。ただし、**最終的に解消したかどうかは、文字起こしでは確認できません。**
